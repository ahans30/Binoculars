# AI判定の閾値評価 プロトコル

結果を見る前に固定した計画です。変更した場合は末尾に理由とともに追記します。

## 目的
`app.py` の `BinocularsDetector`（Qwen2.5-1.5B / Qwen2.5-1.5B-Instruct）が英語の医学論文の文章でAI生成文を判別できるかを評価し、既定の閾値を更新するか、判定ラベルをやめるかを決める。

## データ
データ本体は `data/ai_threshold/` に保存する（購読誌PDFの抜粋を含むため共有しない）。

### 人間の文章（生成AIの普及前）
| 層 | 内容 |
|---|---|
| `ophth_japan` | 眼科、日本の所属、英語、2010〜2018年のPubMed抄録 |
| `ophth_other` | 眼科、日本以外の所属、英語、同期間 |
| `med_japan` | 疫学研究、日本の所属、英語、同期間 |
| `med_other` | 疫学研究、日本以外の所属、英語、同期間 |
| `en_long` | 手元の英語PDFの本文抜粋（長文）、PDF作成日が2018年以前 |

### AI文
- 生成元: Gemma 4 E4B、Qwen3.5 9B（いずれもLM Studioのローカル実行）、Claude Opus 5.5。
- 新規作成: 人間の抄録の題名だけを渡して抄録を書かせる（題名を対応させて分野をそろえる）。
- 推敲: 人間の抄録を渡して学術英語に磨かせる。AI利用の実態に近いが、内容の大半は人間由来なので主解析とは別に報告する。
- 未発表原稿の文章はどの段階でも入力に使わない。プロンプトと生成条件は各レコードに記録する。

## 主解析
人間の文章を層ごとに半分に分け、片方（校正用）で閾値を決め、もう片方（検証用）とAI文で評価する。

1. 全文のスコアでAUCを算出する（低いほどAI）。
2. 校正用の人間文の偽陽性率が1%、5%になる閾値を決め、検証用の偽陽性率とAI文の検出率を求める。
3. 95%信頼区間はブートストラップ（2,000回）で求める。比率が0か1に近い場合はWilson法も併記する。
4. 生成元、人間の層、長さ（50、100、200語相当と全文）ごとにも報告する。

## 判定基準
**新規作成文**について次をすべて満たす場合に限り、既定の閾値を更新して判定ラベルを残す。

1. AUCの95%信頼区間の下限が0.90以上
2. 偽陽性率1%の閾値での検出率の95%信頼区間の下限が0.50以上
3. その閾値で、検証用の `ophth_japan` と `med_japan` の偽陽性率がいずれも3%以下
4. 3つの生成元のすべてで検出率の点推定が0.50以上

満たさない場合は、判定ラベルをやめてスコアだけを表示する変更を提案する。

## 限界
生成元と条件は実際のAI利用の一部にすぎない。AI文には私（Claude）が書いたものを含むが、評価対象を知ったうえで書いているため、参考として扱う必要がある。

## 変更履歴
スコアを算出する前の変更です。

- 日本語を評価の対象外にした。利用者の論文は英語のみのため。日本語の文章に対するこのツールの性能は未評価である。
- LM Studioの生成元を、実際に導入済みの `gemma-4-e4b-uncensored-hauhaucs-aggressive` と `qwen3.8-27b-heretic-abliterated-uncensored` に変更した。いずれも安全機構を外した改変版で、文体が公式版と異なる可能性がある。

## 生成条件
- 新規作成: 各ローカルモデル100件（人間の4層から25件ずつの題名）、Claude 30件。
- 推敲: 各ローカルモデル40件、Claude 10件。
- 長文（Introduction と Discussion）: 各ローカルモデル20件、Claude 4件。
- プロンプトは1つに偏らないよう3種類を順に使う。温度は0.7。
